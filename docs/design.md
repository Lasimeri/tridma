# Design

## The split

| Where | What | Why |
|---|---|---|
| host | llama.cpp built for the host CPU (`GGML_NATIVE=ON`), all ops but the offered multiplies, the host's rows of every multiply, on 14 threads | the host runs scalar code and small ops faster than a round trip to the card costs |
| card | a share of the rows of every weight matrix, resident in GDDR5, multiplied by the matrix service's 120 threads | the card's 512-bit units and 16 GB of fast memory carry the bulk of the weights' arithmetic |
| between | the card's DMA channel 7: activations in, results out; the host daemon's DMA channels: weight uploads | per-line uncached transfers cost a PCIe round trip each; the engine moves blocks |

The ggml backend `libggml_phi.so` (from Intel-Phi-AVX-512-C) is loaded by
`GGML_BACKEND_PATH`. llama-bench loads every backend itself; programs
that parse llama.cpp's common arguments only do so when an option needs
it (a static build always has registered backends, so
`ggml_backend_load_all` is skipped): pass a no-op tensor override such
as `-ot "no_such_tensor=CPU"` to llama-completion or llama-server.

## What the Intel-Phi-AVX-512-C patch changes

On top of `db092f6`:

- **7120A port**: the worker reads the card's core count at run time
  (61 on a 7120A, 57 on a 3120A) instead of a constant; layouts, slots and
  the pool follow it.
- **ggml layout for llama.cpp 4b77dee** (`host/asm/ggml-phi/ggml_layout.inc`):
  regenerated by `tools/ggml-layout-check.c --gen`; two values moved
  (`BUF_BUFT` 88 to 112: `ggml_backend_buffer_i` grew three entries;
  `GGML_OP_GLU` 100 to 101: one op inserted before it). The check passes
  on all 100 pinned values; the vtable sizes the glue fills are unchanged.
- **Result pushes by DMA** (`card/vpu/cdma.S`, `matmul.S`): `cdma_push`
  is the card-to-host direction of the existing `cdma_submit` (one
  descriptor format, source and destination swapped; both now post
  through `cdma_post`). `push_data` sends every result through the engine
  first, in pieces of at most 983,040 bytes via the landing area, and
  falls back to the earlier paths only on a refusal or a timeout. A
  request's push went from 0.48-0.59 ms to 0.039 ms in steady decode.
- **DMA counters** (`cdma_stats`, `OFF_CDMA_STATS` 192 in the control
  area, `vpu_proto.h`): bytes and copies each way, stored after every
  reply beside `OFF_STATS`.
- **Slots beside the pool** (`-O`, `worker.S`, `sched.S`): each core has
  four hardware threads; the matrix pool keeps 0 and 3, a slot takes 1
  and 2 of the same cores, the slot's control thread the last core's
  thread 1. Used by the preload path; idle in design A.
- **Streamed weights** (`PHI_GGML_STREAM=1`, `backend.S`, `glue.S`): weights
  stay in the shared window in host RAM and the card pulls each matrix
  per multiply (the matrix service's existing `a_id 0` path). Measured
  0.98 GB/s on a cold pull and 2.23 GB/s steady through the block
  device; only for models that fit the 4 GiB window, so off by default.
- **Preload fix** (`host/asm/phi512/sigill.S`): a thread's first SIGILL
  installs the alternate stack and returns, so the instruction faults
  again on that stack; before, the first region of a new thread ran on the
  program's stack with only the red zone writable back, and lost a
  callee's frame (a divide error in llama.cpp's `mul_mat`).

Every change has its sibling `.md` updated in the patched tree
(`scripts/check-docs.sh` passes). Gates run on the 7120A with the
patched worker: `phi-vpu matmul-check` (every weight format, mixtures,
several matrices a request, the fused feed-forward: all ok), and
`tools/vpu-layout-check.c` for the control area.

## What the phitop patch changes

phitop's pcie line came only from the host daemon's counters (bytes it
moved itself); the worker's channel 7 is card-owned and never passes
through the daemon. The patch copies the worker's `OFF_CDMA_STATS` line
into the snapshot, derives bytes a second each way, and starts the pcie
line with `card dma in X, out Y`, ahead of the daemon's numbers, so a
132-column frame keeps it.

## The other path, and why it is not the default

The same patches also carry an instruction-level path: llama.cpp built
with `-mavx512f` (F only; KNC has no VL, BW or CD forms) running under
the preload `libphi512-c.so`, which catches each AVX-512 instruction's
SIGILL and runs the surrounding function on the card. It runs, but
measured 0.05-0.06 tok/s prompt and 0.01 tok/s decode on a 2B model and
0.01 tok/s on the 35B: every non-matmul op becomes a card round trip of
milliseconds, and the scalar code gcc emits for those ops is EVEX, which
the host cannot run itself. Multi-threaded hosts deadlock on the
preload's single handler lock; one host thread is the working setting.
